# Development and documentation

## Sources and tooling

| Content | Source |
| --- | --- |
| Runtime | Go packages under `internal/` and `cmd/limanix/` |
| Handwritten guides | Markdown files under `docs/pages/` |
| Configuration reference and default TOML | Types, tags, and defaults in `internal/config/` |
| CLI reference | Cobra command definitions in `internal/cli/` |
| Documentation version | `internal/buildinfo.Version` through `cmd/docsgen` |

Taskfile includes the shared containerized Go tasks from
`mr-chelyshkin/tasks` at `v0.0.3`. Go checks, Linux guest-agent generation, and
documentation builds run in the Go CI image. Native release binaries build on
macOS with CGO enabled, Apple's SDK, and the virtualization and network
entitlements used by Lima.

Install Task `3.53.1` and use Docker for the containerized checks and documentation
tasks below. Native `ci/build` runs directly on macOS with the host Go toolchain
and Xcode command-line tools.

The repository's `vm/` directory is ignored by Git. You can keep machine-specific
configurations and environment values there and select one explicitly with
`limanix create --config vm/NAME/limanix.toml` or the corresponding `update` command.

The shared Go image and compiler are pinned to `1.27.1`.
Both application and documentation modules declare `toolchain go1.27.1`.
Go caches retain the downloaded compiler and dependencies between container runs.

Linux tests and reference generation use `-tags=osusergo` and `USER=limanix`.
The shared container runs with the host UID, which may have no `/etc/passwd`
entry inside the image. Go's user lookup fallback can obtain the username from
`USER` in that case. Lima resolves its host user during package initialization;
these settings allow tests and reference generation to run with a UID such as
`501` without adding an account to the container image.

Hugo builds the static documentation with Hugo Book and Mermaid diagrams.
Taskfile pins Hugo Extended to `v0.166.0`; `docs/go.mod` and `docs/go.sum` pin
Hugo Book to `v0.14.0`. Both Hugo and Limanix use the `go1.27.1` compiler.
The site includes the generated default TOML as a download
and reads its version from the metadata generated by `cmd/docsgen`.

## Check the Go application

Run the same tasks locally as in CI:

```console
task ci/fmt ci/lint ci/test ci/vuln
```

The `ci/test` task runs `cmd/bundle-guestagent` in the Go container before compiling tests.
The generator verifies existing manifests, archive hashes, and ELF architectures,
and rebuilds the assets when validation fails. Generated archives and their
manifest are ignored build artifacts.

On macOS, install the Xcode command-line tools and run:

```console
task --yes ci/build
```

`ci/build` chooses both macOS architectures, binary names, and release flags in
the project's Taskfile. It generates or verifies guest agents through the host
Go toolchain, builds with CGO enabled, and signs and
verifies both binaries with `.github/assets/vz.entitlements`. The deployment
target is macOS 13.0 and is checked in each binary's Mach-O metadata. It does not
need Docker. `RELEASE_TAG` sets the embedded release version; an unset value keeps
the development version.

Vulnerability checks and tests run separately through `ci/vuln` and `ci/test`;
`ci/build` does not invoke them.

The PR and tag workflows are defined in this repository. Go and documentation
checks run on Ubuntu through `mr-chelyshkin/actions/invoke-taskfile@v1`.
The PR workflow also uses `check-changelog-label@v1` and `check-job-results@v1`.
Native build jobs use `actions/setup-go` and install Task `3.53.1`, then run
`ci/build` on `macos-26` with Apple's installed SDK. Each checkout generates the
guest agents it needs; no SDK archive or custom cross-compilation image is
required.

The tag workflow uses `check-tag-branch@v1` to check that the tagged commit
belongs to `main`. It runs formatting, lint, and vulnerability checks before
building and uploading both binaries. Tests run in the PR workflow, which invokes
`ci/test` with the race detector; the tag workflow does not rerun them. GitHub
Release publication waits for the binaries and documentation checks. Guest boot,
mounts, and networking are tested separately on a local Mac.

## Build the site

After changing configuration types, defaults, descriptions, or CLI definitions:

```console
task ci/docs
```

This runs `cmd/docsgen`, then Hugo Extended, through `golang:_go/tool` in the Go
container. The generator updates `limanix.example.toml` and writes
CLI/configuration fragments and version metadata to `docs/_generated/`.
The example and generated fragments are ignored build artifacts. Change their
Go sources instead of editing or committing the generated files.

Hugo builds the site from the generated content and the handwritten pages into
`build/docs/`. Warnings fail the build. HTML output is a build artifact.
Keep handwritten pages in `docs/pages/`, templates in `docs/layouts/`, assets in
`docs/assets/`, Go sources, and documentation configuration and dependency files
in Git.

## Preview the site

```console
task docks/preview
```

Open <http://127.0.0.1:8070>. The task generates the Go references before starting
Hugo's development server through `golang:_go/tool`. The preview renders in
memory and leaves `build/docs/` unchanged. Markdown and presentation changes
rebuild the site and refresh the browser. After a Go model or command change,
restart the task to regenerate the reference fragments. Press **Ctrl+C** to stop
the preview.

To select another port:

```console
task docks/preview DOCS_PORT=8001
```
